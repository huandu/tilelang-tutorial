# 图 5：复杂度结论的量级对比

**用途**：正文 §3.6、§6。

数据来源：`code/03-complexity-tables/complexity_tables.py` 在
`N = 1,048,576, k = 512, B = B2 = 1024` 下的输出。**全是公式算出来的渐近量级，
不是实测**；`torch.topk` 那一行是本章 §6.2 的**粗糙代价模型**，不是测量值。

```text
一项                                   元素数        相对 N
──────────────────────────────────────────────────────────
读一遍输入  N                        1,048,576      1
E[W] ≤ (1+k/B2)·L·H_m                   28,835      0.0275
O(k·log(N/k))                            3,904      0.0037
torch.topk 的代价模型
  ≈ N + N·log2(k)                   10,485,760     10
```

## 读图提示

* 三条 DeepSelect 相关的量级都比 `N` 小一到三个数量级：**TopK 的额外计算量不是
  主项，读一遍输入才是**。
* `E[W]` 绝对随 `N` 增长，但只按 `log N` 涨——所以相对 `N` 越来越小
  （`code/03` 的 Table 1 从 `N=4096` 的 `bound/N=1.95` 一路降到 `2^24` 的 0.0024）。
* 最后一行的 `N·log2(k)` 是**示意性的排序代价**：它要说明「`torch.topk` 比
  DeepSelect 多出一个与 `N` 同阶的趟」，而不是精确预测某个实现。
* 这张图上的任何数字都**不能当作带宽或加速比**；实测口径见 §6 与
  `.../DeepSelect/README.md:39-62`。
