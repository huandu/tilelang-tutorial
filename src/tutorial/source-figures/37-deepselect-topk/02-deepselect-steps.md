# 图 2：算法三步骤与候选缓冲区的增长

**用途**：正文 §2.2、§2.3。

来源：伪代码与文字说明见
`.../DeepSelect/docs/DeepSelect-deep-dive.zh.md:9-13`（三个步骤）、`:17-39`（伪代码）、
`:41-49`（阈值单调、候选上界、额外空间）。

```text
        ┌────────────────────────── 循环 ──────────────────────────┐
        │                                                          │
 ① Scan │  按随机块序取一个 B 块（每块连续；全序列只读一遍）
        │      │
 ② Filter│     └─► 只保留 > T 的元素 → 追加到 topk_candidate
        │              │                （T 初值 −inf，所以第一轮全收）
 ③ Compact│            └─► len ≥ k + B2 时：RadixSelectTopK 精简回 k 个
        │                     T ← 这 k 个里的最小值
        └──────────────────────────────────────────────────────────┘
                                    │
                          扫描结束 → 最后一次 Compact → 返回 top-k

   候选缓冲区大小随扫描的变化（示意）：

     k+B2 ┤      ╱╲          ╱╲
          │     ╱  ╲    ╱╲  ╱  ╲     ← 每次触发 compact 就掉回 k
       k  ┤ ╱╲ ╱    ╲  ╱  ╲╱    ╲
          └────────────────────────────► 扫描进度
            增长越来越慢（阈值 T 只升不降）
```

## 读图提示

* 三个步骤里，**只有 ③ 的规模与 N 无关**：① 要把输入读一遍，② 是纯筛选，
  ③ 只在大小为 `O(k+B+B2)` 的候选集合上做。
* 缓冲区**不会无界增长**：报告给的上界是 `len(topk_candidate) <= k + B2 + B`
  （`...zh.md:47`）——触发阈值是 `k+B2`，而一个块最多再塞进 `B` 个。
* 阈值 `T` 只升不降（`...zh.md:41`），所以「后面的元素被接受的概率越来越小」——
  这就是图上「增长越来越慢」的原因，也是 §3 证明要量化的东西。
