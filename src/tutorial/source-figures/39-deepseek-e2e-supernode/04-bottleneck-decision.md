# 图 4：瓶颈定位的检查顺序

**用途**：正文 §5.1、§5.2。

**事实来源**：每一步的判据都取自前面章节，逐条标注在正文 §5.2 的表里。

```mermaid
graph TB
    S0(["慢的 kernel / 慢的一步"]) --> S1["① 判类：算 flops/bytes<br/>与平衡点比大小（第 28 章）"]
    S1 --> S2["② 哪条 PIPE 满？<br/>aic_mad / aic_fixpipe / mte2 / aiv_vec"]
    S2 --> S3["③ 通信有没有重叠？<br/>三层重叠（第 38 章 §9.3）"]
    S3 --> S4["④ layout 与对齐？<br/>ND2NZ / 512B / bank（第 36 章）"]
    S4 --> S5["⑤ 启动开销与小 kernel？<br/>融合 / 入图 / persistent"]
    S5 --> S6["⑥ 回头用对拍复核模型<br/>效率 >100% 就是公式错（第 28 章 M8）"]
    S6 -.->|判类变了| S1
```

**要点**

* 这是**检查顺序**，不是「六件事都要做一遍」。多数情况下前两步就能定位。
* ②/③ 的先后取决于 ① 的判类结果：compute-bound 先看 ②，
  通信占比高的先看 ③（正文 §5.4 的走查演示了这条）。
* 走不到 ② 而直接进 ⑤，通常意味着这个算子已经接近它的形状能给的极限。
