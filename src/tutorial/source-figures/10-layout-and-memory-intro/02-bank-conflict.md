# 图 2：bank conflict 的发生与两种消除方式

对应正文第 2.3、2.4 节。例子取自 CUDA 官方最佳实践里那个最经典的场景：一个
`32×32` 的 `float` 共享内存 tile，warp 的 32 个线程去读**同一列**。

硬件前提（`../tilelang-corpus/05-nvidia-backend/raw/nvidia-cuda-best-practices.md:1545-1554`）：

* shared memory 被划分为等宽的 **bank**，可以同时访问；
* compute capability 5.x 及以后，**每个 bank 每个时钟周期 32 bit（4 Byte）**，
  连续的 32-bit 字依次落到连续的 bank；
* warp 是 32 线程，bank 也是 32 个，所以 **一个 warp 里任意两个线程都可能撞 bank**；
* n 个地址落在 n 个不同 bank 上时，一次访存就完成；多个地址落在同一个 bank 上时，
  访存被**串行化**（唯一例外是多个线程访问同一个地址时的广播）。

## 冲突前：行主序、stride = 32

```text
32×32 float tile，行主序，行长 32 个 4B 字。warp 里第 t 个线程读 column-0 的第 t 个元素：

  addr(t) = t * 32 (单位: 字)
  bank(t) = (t * 32) mod 32 = 0        ← 32 个线程全部落在 bank 0

  bank:   0    1    2    3   ...   31
        ┌────┬────┬────┬────┬─────┬────┐
        │████│    │    │    │ ... │    │   █ = 本周期被请求的 bank
        └────┴────┴────┴────┴─────┴────┘
          32 路冲突 → 原本 1 个周期的访存被拆成 32 个串行请求
```

## 方式一：padding，把 stride 改成 33

```text
给每行多留 1 个字，行长变成 33：

  addr(t) = t * 33
  bank(t) = (t * 33) mod 32 = t        ← 32 个线程恰好落在 32 个不同 bank

  bank:   0    1    2    3   ...   31
        ┌────┬────┬────┬────┬─────┬────┐
        │████│████│████│████│ ... │████│   每个 bank 恰好 1 个请求
        └────┴────┴────┴────┴─────┴────┘
          无冲突 → 1 个周期完成
```

## 方式二：XOR swizzle，不改 stride，只改行内偏移

TileLang 的 bank swizzle 是**按行做异或**：把「第 s 行、第 c 个 16B 单元」搬到
第 `c xor s` 个单元（128B swizzle 用 3 bit，64B 用 2 bit，32B 用 1 bit）。
这样**不需要 padding，容量不膨胀**，代价是行列地址计算里多一次异或。

```text
128B swizzle 的一个 8 行周期（fp16，一个 16B 单元 = 8 个元素）：
  物理列单元 c' = c xor s   （s = 行号 mod 8，c = 列单元号 mod 8）

          逻辑列单元 c →  0    1    2    3    4    5    6    7
  s = 0  (行 0)           0    1    2    3    4    5    6    7
  s = 1  (行 1)           1    0    3    2    5    4    7    6
  s = 2  (行 2)           2    3    0    1    6    7    4    5
  s = 3  (行 3)           3    2    1    0    7    6    5    4
  s = 4  (行 4)           4    5    6    7    0    1    2    3
  s = 5  (行 5)           5    4    7    6    1    0    3    2
  s = 6  (行 6)           6    7    4    5    2    3    0    1
  s = 7  (行 7)           7    6    5    4    3    2    1    0

  每一行都是 0..7 的一个排列（双射），整体仍是 8×8 的置换 → 数据不丢；
  竖着看每一列的取值在 0..7 之间也恰好各出现一次 → 列访问不再撞同一个 bank。
```

## 一句话总结

* pad / swizzle 都只是**改物理 offset 的公式**，不是改数据本身；
* padding 简单、容量变大；swizzle 不增容量、地址计算更贵；
* 两者都在消同一个东西：**同一个 warp 内多个线程命中同一个 bank**。

图中的异或表与 bank 编号都由 `../code/01-layout-algebra/layout_algebra.py`
（纯标准库）复算得到，可在任意机器重跑核对；公式来源见该目录 README。
