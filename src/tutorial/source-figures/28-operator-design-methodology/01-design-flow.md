# 图 1：拿到一个新算子的设计流程

**用途**：正文第 1.2 节。这张图是本章的总纲，**代码是最后一步，不是第一步**。

```mermaid
flowchart TD
    A["拿到一个新算子<br/>PyTorch 参考实现 + 真实 shape"] --> B
    B["① 建模：算出 flops, bytes<br/>算术强度 · 访存下界 · 机器平衡点"] --> B1{"AI 与平衡点比"}
    B1 --> C
    C["② 定 tile 尺寸与存储位置<br/>片上容量 / 寄存器 / 指令形状 / 并行度"] --> C1{"四条约束都过吗"}
    C1 -- 否 --> C2["缩小 tile 或换分块轴<br/>不要改算法"]
    C2 --> C
    C1 -- 是 --> D
    D["③ 定流水结构<br/>哪些迭代可以重叠 · 需要几份缓冲"] --> D1{"搬运延迟 / 计算周期"}
    D1 -- 接近 1 --> D2["不加流水<br/>num_stages 保持 1"]
    D1 -- 大于 1 --> D3["加多缓冲<br/>份数 = 1 + ceil 延迟/周期"]
    D2 --> E
    D3 --> E
    E["④ 判断是否需要特殊指令 / 特殊布局<br/>张量核 · TMA · 异步 · swizzle · fractal · dual_copy"] --> E1{"默认降级路径够快吗"}
    E1 -- 是 --> F
    E1 -- 否 --> E2["引入特殊路径<br/>并写下它带来的新约束"]
    E2 --> F
    F["⑤ 写代码<br/>①–④ 的结论变成 tile 尺寸、scope、num_stages、注解"] --> G
    G["⑥ 测：与模型对账<br/>差多少 · 差在哪一条约束上"] --> G1{"离下界近吗"}
    G1 -- 否 --> H["回到 ①–④ 里最可疑的那一步"]
    H --> B
    G1 -- 是 --> I["交付：口径、判据、边界条件一起写下来"]
```

## 流程里最容易跳过、也最贵的两步

| 步骤 | 跳过它的典型后果 | 本章对应 |
| --- | --- | --- |
| ① 建模 | 花了三天调参，最后发现算子的 AI 比平衡点低两个数量级，调参空间本来就没有 | 第 2 节 |
| ② 定 tile | `block_M=256, block_N=256` 编不过，或者编过了但掉到 1 block/SM | 第 4 节 |
