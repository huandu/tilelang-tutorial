# 第 02 章 习题

共 13 题：概念题 4 道、计算题 3 道、代码阅读题 3 道、动手题 3 道。
每题标注难度（★ / ★★ / ★★★）与是否需要真实硬件。
**本章所有题目都不需要 GPU/NPU**；标“否”的题目在任意有一台装了 Python 3.9+ 的机器上即可完成。
答案与解题思路见 [solutions.md](solutions.md)。

约定：除非题目另说，访存一律按本章记账法（每个输入读一次、每个输出写一次、中间量不计、
超越函数记 1 FLOP），机器用 H200 标定参数（729.3 TFLOPS fp16 / 4502 GB/s / 平衡点 162 FLOP/Byte）。

---

## 概念题

### E1（★，不需要硬件）

把一次训练迭代的四个阶段，前向、反向、优化器、通信，分别归类到
“compute-bound / memory-bound / 纯搬运”，并对每一个给出**一句话**的理由。
对优化器那一段，请给出“每个参数要搬多少字节”的来源（哪份文档、哪个张量）。

### E2（★，不需要硬件）

同一个 attention 算子，在 prefill 与 decode 两段里的判据相反。请用算术强度的语言解释
这件事：prefill 里每读一个字节的数据做多少次乘加？decode 里呢？
（提示：decode 的 query 只有 1 个 token。）

### E3（★★，不需要硬件）

本章说“厂商规格和能跑到的不是一个数”。请举出本章用到的两个具体事实支持这句话，
并说明它们各自的测量/标定条件。如果用 989.5 TFLOPS、4800 GB/s（厂商规格）而不是
729.3 TFLOPS、4502 GB/s（标定值）来算平衡点，会得到什么值？这个差别会改变本章
哪些算子的判据、不会改变哪些？

### E4（★★，不需要硬件）

一条 $k$ 个算子的逐元素链，融合后这条链的访存从 $2k$ 趟降到 $2$ 趟。
那么是不是 $k$ 越大收益越大？请说明“这条链本身的收益”和“端到端收益”分别由什么决定，
并给出一个“$k$ 很大、端到端收益却很小”的场景。

## 计算题

### E5（★★，不需要硬件）

手算 LayerNorm，$M=4096$、$H=4096$、fp16：

1. 融合实现的访存量与算术强度；
2. “均值一趟、方差一趟、归一化+仿射一趟”这种朴素拆分的访存量与算术强度；
3. 在 H200 标定参数下，两者的时间下界各是多少；
4. 如果把 $H$ 从 4096 改成 512，结论会不会变？为什么？

### E6（★★，不需要硬件）

用 H100 的厂商规格（1000 TFLOPS fp16 / 3.0 TB/s，平衡点 333）：

1. 手算 $2048^3$ 的 fp16 GEMM 的算术强度与判据；
2. 边长是多少时它刚好落在脊点上（算术强度等于平衡点）？给出表达式而不是只给数字；
3. 用本章脚本验证你的两个答案。

### E7（★★★，不需要硬件）

$\text{attention}$ prefill，$B=1$、32 head、$d=128$、$S=8192$、fp16：

1. 手算“把 $S\times S$ 的分数矩阵落到显存”这一版的总访存量（写出每一项是什么）；
2. 手算 flash 风格（分数不落显存）版本的访存量；
3. 两者的比值是多少？如果把 $S$ 从 8192 改成 16384，这个比值会怎么变？
   由此解释为什么这个中间量被称为 $O(S^2)$ 问题。

## 动手题

### E11（★★，不需要硬件）

运行：

```bash
python3 code/01-op-traffic-model/op_traffic.py
python3 code/01-op-traffic-model/op_traffic.py --machine h100-spec
```

列出两份输出中判据（memory-bound / compute-bound）**发生翻转**的算子，以及**没有翻转**的算子。
对每一类各挑一个，解释翻转或不翻转的原因。再回答：为什么“逐元素加”不管用哪台机器
都不可能变成 compute-bound？

### E12（★★★，不需要硬件）

先用默认参数跑 `code/02-step-budget/step_budget.py`，再把 `--seq-len` 依次改成 512、
4096、32768、131072：

1. 记录每个序列长度下“前向”“反向”“优化器”“通信”的占比；
2. 找出占比变化最快的那一段，并解释为什么是它；
3. 结论里必须提到：这四个阶段里，哪一段的**绝对时间**几乎不随序列长度变化。

### E13（★★★，不需要硬件）

给下面两个算子各写一个账本函数（可以照 `op_traffic.py` 里 `layernorm` 的写法），
加进脚本并跑通：

1. **SiLU 激活**：$y = x\cdot\sigma(x)$，$N$ 个元素；
2. **RoPE 的旋转部分**（不考虑 norm，不考虑写 KV cache）：
   对 $B\times H\times S\times d$ 的张量，按 dim 两两配对，每对做
   $y_1 = x_1\cos\theta - x_2\sin\theta$、$y_2 = x_2\cos\theta + x_1\sin\theta$（$\theta$ 已预计算）。

对每个算子：写出 `flops`（要给出你采用的每元素 FLOP 计数与理由）、`bytes`、
算术强度、在 H200 标定参数下的时间下界与判据。
最后回答：如果把它们和“残差相加”融合进一个 kernel，访存量会怎么变？
