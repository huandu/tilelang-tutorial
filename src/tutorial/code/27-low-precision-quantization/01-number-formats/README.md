# 示例 01：低精度格式的范围与精度是怎么算出来的

## 目的

正文第 2 节的三张表（有效位与 `u`、表示范围、E8M0 值域）都由这个脚本产出。
做法是**枚举位模式**而不是抄参数：

* fp16 用 numpy 的 `finfo`；bf16 按 `1+8+7`、bias 127 直接算边界；
* fp8 e4m3（OCP FN）枚举全部 256 个位模式，命中 `0x7f`/`0xff` 时跳过 NaN；
* fp8 e5m2 同样枚举，指数全 1 视为 inf / NaN；
* fp4 e2m1 枚举 16 个位模式；
* E8M0 枚举 255 个指数编码。

## 运行前提

Python 3.9+ 与 numpy。**不需要 GPU / NPU**。

## 运行命令

```bash
python3 number_formats.py
python3 number_formats.py --show-fp4
```

## 这张表怎么用

* `u = 2^-p` 是第 12 章容差模型的唯一输入；fp8 的 `u` 是 6.25e-2，
  比 bf16 大一个数量级，这直接决定了 fp8 的对拍必须换一套判据。
* fp8 e4m3 的 `448` 是权重/激活量化的关键常数：锁定版本的 MXFP8 量化就是
  `ceil_to_ue8m0(amax / 448)`（见 `examples/blockscaled_gemm_sm100/`），
  保证除以 scale 之后一定落在 e4m3 的值域内。
* e5m2 的动态范围（9.6 个数量级）比 e4m3（5.4 个）宽得多，代价是有效位只有 3 位。
  这就是“梯度用 e5m2、前向用 e4m3”这条经验的来源。
* E8M0 不能表示 0 与负数：它是**缩放因子**，不是数据格式。

## 注意事项

* bf16 的边界是**按布局推出的解析值**，不是枚举位模式的结果；numpy 没有原生 bf16，
  所以这里没有做“枚举 + 往返”的自检。正文引用这些数字时按解析值处理。
* e4m3 的舍入规则（round-to-nearest-even）没有在这里实现，只有码本本身；
  量化时的舍入在 `02` 里用“最近码本值”近似，平局处理与硬件不一定逐位一致。
