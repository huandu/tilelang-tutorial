# 示例 03：误差预算、参照选择与累加器精度

## 目的

把第 12 章的容差模型（`u` 与 `u/sqrt(K)`）推广到 fp8 / fp4 / int8 / int4，
并用三组实验回答正文第 5 节的问题：

* **实验 A**：同一份量化输入，分别以「原始值」和「量化后的值」为参照，误差差多少？
  用来量化「参照选错」的后果。
* **实验 B**：K 从 64 到 4096，`u/sqrt(K)` 这个缩放律对每种格式成立到什么程度？
* **实验 C**：输入完全一样，只换累加器（fp16 顺序累加 / fp32 / 分段后 fp32 汇总）。

## 运行前提

Python 3.9+ 与 numpy。**不需要 GPU / NPU**。

## 运行命令

```bash
python3 error_model.py
python3 error_model.py --trials 400 --lengths 64,256,1024,4096
```

## 三个判据

**（一）参照选错会差 4 个数量级以上。** fp16 是 `3.3e-5` 对 `5.9e-9`；e4m3 与 e2m1
的「对量化值」误差直接是 0——4 位尾数的乘积只有 8 位有效位，fp32 能精确表示，
连累加都不丢位。把「量化前的 fp32 结果」当参照，正常的量化误差会被判成逻辑错误。

**（二）`u/sqrt(K)` 对浮点是量级模型，对 fp4 失效。** fp16 / bf16 / e4m3 的
「实测 / 预算」稳定在 0.44–0.58（与第 12 章的 0.5 一致）；int8 是 1.27–1.47
（均匀量化比浮点更接近最坏情形）；e2m1 却是 2.58——4 位浮点的相对间距随指数变化
太剧烈，小数值的相对误差远超 `u`。**用 fp4 时不要套用 fp16 的容差公式，
要在真实数据分布上实测。**

**（三）累加器是独立的一档误差。** 同一份 fp16 输入，`fp16 顺序累加` 的中位误差是
`1.24e-4`，换成 fp32 累加变成 `1.24e-9`；而「32 段 fp16 部分和 + fp32 汇总」落在
中间（`2.06e-5`）。这就是 split-K 能保住精度的原因：每段的舍入误差只与该段长度有关，
跨段用 fp32 连接不会再放大。

## 注意事项

* 实验 B 的「预算」用的是 `u`，没有考虑数据分布与相关性；它只是量级判断。
* 实验 C 的 fp16 顺序累加用 `np.cumsum(..., dtype=np.float16)` 模拟：每一步都在
  fp16 里舍入。它没有模拟硬件的 fused multiply-add（乘积本身不额外舍入），
  所以真实 kernel 的累加误差可能比这里**小**一点。
* 真实 kernel 还有 epilogue 的 cast、分块累加的顺序差异，这些都不在本模型里。
