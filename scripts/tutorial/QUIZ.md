# 章节自测题规范（TileLang 教程）

每个章节一套**客观题**，用于在线评分。文件路径：

```
src/tutorial/quiz/<chapter-slug>.json
```

## 格式

```json
{
  "chapter": "01-why-tile-dsl",
  "items": [
    {
      "id": "q1",
      "stem": "题干，一到两句，问一个明确的知识点。",
      "options": ["选项 A", "选项 B", "选项 C", "选项 D"],
      "answer": 2,
      "explain": "为什么是这个答案；指出依据在正文哪一节。"
    }
  ]
}
```

| 字段      | 约束                                                                   |
| --------- | ---------------------------------------------------------------------- |
| `chapter` | 必须等于文件名（不含 `.json`）                                         |
| `items`   | **5–8 题**                                                             |
| `id`      | `q1`、`q2`… 按顺序                                                     |
| `stem`    | 中文，≤ 120 字，一道题只问一件事                                       |
| `options` | **恰好 4 个**，每个 ≤ 60 字，互不相同                                  |
| `answer`  | 0–3 的整数，指向唯一正确项                                             |
| `explain` | 1–3 句，说明正确项为什么对、错误项为什么错（至少点出最容易误选的那个） |

## 出题要求

1. **只考本章内容**，且只考正文里明确写过的东西（可以引用小节号，如「见 §2.3」）。
2. 覆盖要均衡：概念/原理、代码与 API 细节、设计取舍、常见陷阱各出一点。
3. **干扰项必须是「看起来对」的常见误解**，最好直接来自该章「常见坑」小节；不要用明显荒谬的选项凑数。
4. 不要出需要真机运行才能知道答案的题（本机无 GPU/NPU）。
5. 不要把章节标题原样抄成题干；要问「为什么」「哪个更合适」「这句话错在哪」。
6. 数字类选项（容量、步数、粒度）必须与本章正文一致，不要引入新数字。
7. 答案分布要打散，不要让正确项集中在同一个位置。

## 自检

写完运行：

```bash
node scripts/tutorial/check-content.mjs
```

它会校验 JSON 结构、选项数量、`answer` 是否越界、题目数量是否在 5–8 之间，以及图表规格的
合法性与 `id` 一致性。全部通过才算完成。
